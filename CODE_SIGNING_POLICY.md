Oreste AI – Code Signing Policy
Project

Project: Oreste AI
Repository: https://github.com/testonuovo/oreste-ai
License: MIT License

Oreste AI is an open-source project developed and maintained through
its public GitHub repository.

Current Signing Status

Oreste AI Windows releases are currently not digitally signed.

The project intends to use code signing for future eligible Windows
releases in order to help users verify the authenticity and integrity
of the released software.

Planned Code Signing

The project intends to apply for code signing through the
SignPath Foundation program.

If the project is accepted, eligible releases may be signed using
code-signing infrastructure provided through SignPath Foundation.

SignPath Foundation approval is not currently granted and no current
release should be considered SignPath-signed.

Source Code

The source code used to produce releases is maintained in the public
GitHub repository:

https://github.com/testonuovo/oreste-ai

Releases should be produced from source code contained in this
repository.

Release Artifacts

The project may distribute Windows software including:

Oreste AI
Oreste AI Cleaner
Windows installers and related release artifacts

The official release artifacts are published through the project's
GitHub Releases.

Maintainers and Roles
Authors

Authors and contributors create and maintain the source code.

Reviewers

Reviewers examine source-code changes and release-related changes
before they are included in an official release.

Approvers

Authorized project maintainers approve official releases for
publication and, when applicable, code signing.

At the current stage of the project, the primary maintainer may
perform multiple project roles. The project will maintain appropriate
separation of duties as the contributor and maintainer community
grows.

Build and Release Process

The general release process is:

Source code is maintained in the public GitHub repository.
Changes are reviewed before an official release.
The Windows application is built from the project source code.
The Windows installer is generated from the resulting application.
The release artifact is tested before publication.
The approved release artifact is published through GitHub Releases.
When code signing is available, the approved release artifact is
submitted to the applicable signing process.
Integrity of Releases

Official releases should be generated from the project's maintained
source code.

Release artifacts should not contain intentionally malicious
software, malware, or potentially unwanted functionality.

Security

Project maintainers will investigate reports concerning:

compromised release artifacts;
unauthorized changes to the source code;
compromised signing credentials;
malicious modifications;
vulnerabilities affecting released software.

If a signing credential or release artifact is compromised, affected
releases may be withdrawn or replaced.

Multi-Factor Authentication

Project maintainers responsible for source-code or release
management should use multi-factor authentication on their GitHub
accounts and on relevant signing services when supported.

Privacy

Oreste AI does not intentionally include personal information in
released software.

Personal information submitted to third-party services used for
software distribution or code signing is subject to the privacy
policies of those services.

Changes to this Policy

This policy may be updated as the project, release process, and
code-signing infrastructure evolve.

The current version of this policy is maintained in the public
Oreste AI GitHub repository.
